# engine/ (authored entirely by IBM Bob)

This directory contains no hand-written detector code.

Every Python file in this directory is generated by IBM Bob running headlessly via
`bob run`, managed by the scored keep/discard loop in `tools/forge_loop.py`. No human
writes or edits detector logic here, including the initial baseline, which Bob
creates as iteration 0.

This constraint keeps the project's central claim verifiable:

```bash
git log --format='%an' -- 'engine/*.py' | sort -u    # -> IBM Bob, and nothing else
```

If that command lists only Bob, removing Bob removes the engine. Bootstrapping a
manual baseline to get started would compromise that claim, so we let Bob build from
scratch.

For clarity on attribution: this file (`engine/README.md`) is human-written documentation
and appears under `git log -- engine/`. Every Python file in this directory is authored
entirely by Bob, which is why the verification command filters specifically to
`engine/*.py`. We wrote the explanatory prose; Bob wrote 100% of the detector and runbook code.

## Rules Bob operates under

Defined in `.bob/skills/anomaly-forge-engineer/SKILL.md`:

- May edit only `engine/detect.py` and `engine/runbook.py`
- May never edit `tools/score.py` (the evaluation ruler stays outside the agent's reach)
- May never read `data/telemanom/labeled_anomalies.csv`. Detection runs on telemetry
  alone, and only the scorer evaluates ground truth
- No per-channel hardcoding, no added dependencies, and deterministic output

The held-out split (26 of 82 channels, selected by hashing channel identifiers) gates
whether an iteration is kept. Improvements must generalize across unseen telemetry channels.
